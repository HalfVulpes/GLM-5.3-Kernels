## Why the operators are faster

Small decode GEMMs offer too few independent output tiles to occupy74 SMs.
Split-K distributes disjoint weight segments among more CTAs; tuned tile
sizes avoid idle SMs and excessive shared-memory pressure. The final CTA
reduces FP32 partials in fixed order in the same launch, eliminating a
separate reduction launch. This mainly improves weight streaming.

KDA fusion removes launches and intermediate reads/writes. Stable MoE
split lists fit different expert populations into64/48/32/16-row blocks,
reducing padded work; dedicated group32 Marlin instantiations improve tile
utilization without changing packed weights or scale precision.

Microbenchmarks show real KDA about1.69× and full-row compiled Marlin
4224→2761µs, about1.53×. End-to-end gains are smaller because communication,
the remaining attention/indexer work and scheduling still take time. In one
baseline prefill-step profile, NCCL allreduce accounted for roughly600ms
versus146ms for Marlin. CPU operator and GPU kernel trace rows overlap;
they must not be summed. Another machine's ~3000tok/s is not an
operator-only performance promise for this topology.
